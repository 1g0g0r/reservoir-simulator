### Почему непригодны

1. **Ни один файл не соответствует нужной комбинации флагов.** Имя расчёта формируется как
   `case_name = f'Wp={init_Wp}' if heat_losses else f'Wp={init_Wp}_noheat'`
   (`paraphin/constants.py`). Файлов с суффиксом `_noheat` нет вообще — значит **расчёты без
   перетоков тепла не выполнялись ни разу**. Оба ключевых варианта статьи (2 и 3) отсутствуют.
2. **Два расчёта не дошли до предельной обводнённости** (η = 0.972 и 0.946 против нужных 0.98):
   останов произошёл по `Time_end = 9 лет`, а не по критерию 98%. Без выхода на 98% нельзя
   определить ни `t₃`, ни конечный КИН, ни длительность разработки — то есть все ключевые числа статьи.
3. **Старые версии кода.** Файлы `_с.pkl` и `Wp=0.0_processed_data.pkl` содержат поля
   (`J_d`, `J_b`, `I_c`, `mu_o`, `Other params`), которых текущий `save_data_fields.py` не пишет.
   Сопоставлять их с новыми расчётами некорректно.
4. **Разные сетки** (20×20, 25×25, 30×30, 50×50) — сравнивать между собой нельзя.
5. `case_name` **не различает схему теплопотерь** (Ловерье / Винсом—Вестервельд): оба варианта
   пишутся в один и тот же файл и затирают друг друга. Если сравнение схем войдёт в статью,
   `case_name` придётся доработать.

## 2. Что расчёт умеет сохранять (текущий `save_data_fields.py`)

Шаг сохранения — `sol_time_step = dt · 50 = 2.5 сут` (при `dt = 0.05 сут`).

### 2.1. Двумерные поля `(N_t, N_x, N_y)`

| Ключ | Величина | Есть при `W_p = 0`? |
|---|---|---|
| `Pressure` | давление `p`, Па | да |
| `Saturation` | водонасыщенность `S`, д. ед. | да |
| `Temperature` | температура `T`, °C | да |
| `Wo` | массовая доля нефтяного компонента | нет |
| `Wp` | массовая доля растворённого парафина | нет |
| `Wps` | массовая доля взвешенного парафина | нет |
| `Wps dep` | масса отложенного парафина | нет |
| `qp` | скорость отложения парафина | нет |
| `m` | **множитель** пористости `m/m₀` | нет |
| `k` | **множитель** проницаемости `k/k₀` | нет |

⚠ При `init_Wp + init_Wps ≈ 0` флаг `solver._paraphin = False` полностью отключает блок
кольматации, и поля парафина/`m`/`k` **не сохраняются**. Для варианта 3 (`W_p = 0`) будут
доступны только `p`, `S`, `T` и интегральные кривые — этого достаточно, поскольку по заданию
для 5.3 изолинии не строятся.

### 2.2. Интегральные кривые `(N_t,)`

**Мгновенные (`Wells`)**, для каждой скважины `{Injector, Producer}`:

| Ключ | Величина | Единицы |
|---|---|---|
| `<well>_oil` | дебит по нефти `q_o` | м³/с (на график — ×86400) |
| `<well>_water` | дебит по воде `q_w` | м³/с |
| `<well>_total` | дебит по жидкости | м³/с |
| `<well>_eta` | **обводнённость** η | д. ед. |

**Накопленные (`Wells_accumulated`)**: `<well>_Q_oil`, `<well>_Q_water`, `<well>_Q_total`, м³.

**Время:** `Time`, с (на графики — делить на 86400).

### 2.3. Кривая по радиусам пор `(N_t, N_r)`

`plots['fi_o']` — начальная функция пор по размерам `φ₀(r)`;
`plots['fi']` — текущая `φ(r)` в **одной** точке `FI_PROBE = (0, 0)` (ячейка у нагнетательной
скважины). Полное поле `(N_x, N_y, N_r)` не выгружается — весило 75% слоя.

### 2.4. КИН

Отдельным полем **не сохраняется** в режиме с парафином (пишется только в ветке `Other params`
при `_paraphin = False`). Считается одинаково для всех вариантов как

    КИН = Producer_Q_oil / geological_reserves,
    geological_reserves = L_x · L_y · h · m₀ · (1 − S_min) = 200 · 200 · 10 · 0.3 · 0.82 = 98 400 м³

Именно так его считает `graphs.py`. Формула работает и для варианта 3.

## 3. Откуда берутся требуемые статьёй величины

| Требуется в статье | Источник |
|---|---|
| КИН на конец расчёта | `Wells_accumulated['Producer_Q_oil'][-1] / 98400` |
| Длительность процесса, сут | `Time[-1] / 86400` (останов по η ≥ 0.98) |
| `t₁` — прорыв воды | первый индекс, где `Wells['Producer_eta'] > 0` |
| `t₃` — обводнённость 98% | последний слой (`Time[-1]`) |
| `t₂` — середина | `(t₁ + t₃)/2`, ближайший по времени сохранённый слой |
| Поля `T`, `S`, `p` на `t₁`, `t₂`, `t₃` | `Temperature[i]`, `Saturation[i]`, `Pressure[i]` |
| Дебиты нефти/воды | `Wells['Producer_oil'/'Producer_water'] · 86400` |
| Обводнённость | `Wells['Producer_eta']` |
| Накопленная добыча нефти | `Wells_accumulated['Producer_Q_oil']` |

| Положение скважин | `Injector (0,0)`, `Producer (N_x−1, N_y−1)` из `start.py` |

## 4. Расчёты, которые необходимо выполнить

Переключение вариантов — правкой `paraphin/constants.py` (CLI и конфигов нет). Флаги
`heat_losses`, `vinsome_westerveld`, `suffusion` — константы уровня модуля, numba вшивает их в
машинный код, поэтому каждый вариант требует пересборки JIT-кеша (~9 с, сброс кеша по хешу
`constants.py` выполняется автоматически в `paraphin/__init__.py`).

| № | Вариант | `init_Wp` | `heat_losses` | `vinsome_westerveld` | Ожидаемый файл |
|---|---|---|---|---|---|
| 1 | базовый: с перетоками, с парафином | 0.05 | `True` | `True` | `Wp=0.05_processed_data.pkl` |
| 2 | без перетоков, с парафином | 0.05 | `False` | — | `Wp=0.05_noheat_processed_data.pkl` |
| 3 | без перетоков, без парафина | 0.0 | `False` | — | `Wp=0.0_noheat_processed_data.pkl` |
| 4 | *(опционально)* с перетоками по Ловерье | 0.05 | `True` | `False` | требуется доработка `case_name` |

**Оценка стоимости счёта.** По `PERFORMANCE_FINDINGS.md` шаг на сетке 50×50 стоит ≈ 0.94–0.98 мс.
При `dt ≤ 0.05 сут` и длительности ~3500–5000 сут это ~70–100 тыс. шагов, то есть **1.5–3 мин на
вариант** плюс ~9 с компиляции. Все четыре варианта — порядка 10–15 мин. Объём выходных данных —
~250 МБ на вариант с парафином.

## 5. Проблемы, требующие решения до запуска

1. ⚠ **`Time_end` недостаточен.** Базовый вариант при `p_inj = 150 бар` за 3285 сут дошёл только
   до η = 0.972. Требуется увеличить `Time_end` (останов всё равно по η ≥ 0.98), иначе вариант 1
   снова не даст ни `t₃`, ни конечного КИН.
2. ⚠ **Расхождение `p_inj`:** в исходной статье 200 бар, в коде `Pw = 150 бар`. Перепад давления
   определяет и длительность разработки, и время счёта.
3. ⚠ **`case_name` не различает схемы теплопотерь** — блокирует вариант 4.
4. `Wps dep`, `m`, `k` недоступны для варианта 3 (`_paraphin = False`) — на выводы не влияет,
   так как по заданию для 5.3 изолинии не строятся.
5. Кривая `φ(r)` снимается только в точке `FI_PROBE = (0, 0)`, а в исходной статье
   анализировалась ячейка (18, 18) м. Если кривая пор войдёт в новую статью, `FI_PROBE` нужно
   согласовать.
