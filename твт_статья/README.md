# твт_статья

Текст и код статьи для журнала «Теплофизика высоких температур» (ТВТ): влияние теплопотерь
через кровлю и подошву пласта и содержания растворенного парафина на показатели разработки
при заводнении холодной водой. Расчеты используют симулятор `paraphin` из корня репозитория;
этот каталог отвечает только за текст, рисунки и сборку статьи из уже посчитанных данных.

## Что где лежит

Источник (правится руками):

- `article.md` — полный текст статьи (pandoc-markdown, формулы в `$$...$$`). Единственный
  источник правды: обе версии docx собираются из него.
- `исправленные уравнения.docx` — разбор и обоснование правок к математической модели
  (обозначения, знаки, замыкающие соотношения). Раздел «Математическая модель» в `article.md`
  обязан ему соответствовать; распаковывается как обычный zip (`word/document.xml`), pandoc и
  python-docx в окружении нет.
- `PravilaTVT.pdf` — правила журнала для авторов (структура, объем, формулы, рисунки, таблицы).

Код (правится руками, генерирует все остальное):

- `run_cases.py` — прогоняет пять вариантов расчета для статьи (табл. 2), правя
  `paraphin/constants.py` и запуская `start.py` отдельным процессом на каждый вариант
  (флаги вроде `init_Wp`/`heat_losses` — константы уровня модуля, numba вшивает их в
  машинный код, переключить вариант внутри одного процесса нельзя). Перед запуском убедитесь,
  что в `constants.py` стоит сетка `Nx, Ny = 75, 75` (табл. 1) — скрипт ее не трогает.
  Результат — `outputs/data/Wp=*_processed_data.pkl` (по файлу на вариант).
- `make_figures.py` — читает файлы из `outputs/data`, строит все рисунки статьи
  (`figures/*.png` для просмотра, `figures/*.tif` 600 dpi для журнала) и пересчитывает
  **все числа, на которые ссылается текст** в `metrics.md`.
- `make_short.py` — механически урезает `article.md` до объема, разрешенного журналом
  (не более 17 стр. и 10 подрисунков): выбрасывает часть рисунков и раздел «Ограничения
  модели», перенумеровывает рисунки. Результат — `article_short.md`.
- `make_reference_docx.py` — разовый скрипт, генерирует `reference.docx` (шрифты, интервалы,
  поля страницы под правила журнала). Нужно перезапускать только при смене этих правил.
- `core_flood.py` — проверка модели по лабораторным данным (раздел «Проверка модели» статьи):
  керновые опыты Sutton & Roberts (1974) по данным Ring et al. [10] и Wang & Civan [9] и кривая
  выпадения парафина нефти Жетыбая (Li et al., 2024). Внутри — оцифрованные опытные точки и кривые
  чужих моделей с указанием рисунков, откуда они сняты. Без аргументов калибрует `d_p` и `L_k` по
  опыту 1 и считает опыт 2 как прогноз (одномерный керн, `constants.py` правится на время прогона,
  как в `run_cases.py`), `--fit` подбирает эффективные `Tm`, `alpha` по кривой Li, `--check` —
  сходимость по сетке и шагу. Результат — `outputs/data/core_flood.json`, его читает
  `make_figures.py` (рис. 9 и раздел «Сопоставление с экспериментом» в `metrics.md`). Подобранные
  `D` и `Lk` переносятся в `constants.py` руками — полевой расчет считается с ними.
- `run_grid_study.py` — отдельная, необязательная проверка сеточной сходимости базового
  варианта на сетках 50×50/70×70/100×100, флаг `--nr` переключает на сходимость по сетке
  радиусов пор (`Nr`: 15/21/31/45). В саму статью не входит (решение автора).

Генерируется (перезаписывается скриптами выше, руками не править):

- `metrics.md` — сводка чисел по вариантам, отклонений и разложения эффектов.
- `figures/` — рисунки статьи.
- `article_short.md` — журнальная версия текста.
- `article_new.docx` — журнальная версия (docx для подачи в ТВТ).
- `article_full.docx` — полная версия (все рисунки и раздел «Ограничения модели»; за пределы
  журнала выходит осознанно — задел для диссертации и будущих статей).

## Как пересобрать статью с нуля

Все команды — из корня репозитория (`paraphin/`), окружение — как для основного расчета
(`uv pip install -r requirements.txt`). Для docx дополнительно нужен `pandoc`; в этом окружении
он не в `PATH`, а стоит в conda-окружении `docbuild` — вызывайте через
`conda run -n docbuild pandoc ...` или активируйте окружение (`conda activate docbuild`).

```bash
# 0. Проверка по лабораторным данным: калибровка d_p, L_k по керну (десятки минут).
#    Подобранные значения перенести в constants.py (D, Lk) до шага 1.
python твт_статья/core_flood.py

# 1. Пересчитать пять вариантов (табл. 2). Долго - реальное время зависит от вклада
#    кольматации, порядка часа и больше на вариант с активным осаждением парафина.
python твт_статья/run_cases.py            # все варианты
python твт_статья/run_cases.py 1 4        # например, только 1-й и 4-й

# 2. Перестроить рисунки и пересчитать все числа текста
python твт_статья/make_figures.py

# 3. Обновить числа и формулировки в article.md по свежему metrics.md (руками)

# 4. Собрать журнальную версию текста из полной
python твт_статья/make_short.py

# 5. Собрать docx
pandoc твт_статья/article.md -o твт_статья/article_full.docx \
    --reference-doc=твт_статья/reference.docx
pandoc твт_статья/article_short.md -o твт_статья/article_new.docx \
    --reference-doc=твт_статья/reference.docx
```

Шаг 3 нельзя автоматизировать полностью: `metrics.md` дает готовые числа для таблиц 3-4 и
абзацев результатов, но описательный текст (координаты минимумов, диапазоны полей, разности
между вариантами) пишется по нему руками, чтобы сохранить связный текст статьи.

## На что обратить внимание

- **`make_short.py` дублирует числа руками.** Подписи рисунков (`CAPTIONS`) и сжатый абзац
  «Ограничения модели» (`LIMITATIONS`) — это literal-строки внутри скрипта, а не то, что
  берется из `article.md` автоматически. Поменяли числа в `article.md` (например,
  содержание парафина `w_p` или множитель Кригера—Догерти) — обновите те же числа в начале
  `make_short.py`, иначе журнальная версия разойдется с полной.
- **`run_cases.py` и `run_grid_study.py` правят `paraphin/constants.py` временно** и
  восстанавливают его в `finally`. Если прогон прервать жестко (`kill -9`, а не `Ctrl+C`),
  восстановление не отработает — проверьте `git diff paraphin/constants.py` после прерванного
  прогона.
- **Имена файлов результатов зависят от `init_Wp`/`heat_losses`.** Меняете содержание
  парафина в `run_cases.py` (`CASES`) — меняются и ожидаемые имена `outputs/data/*.pkl`;
  их нужно поправить и в `ARTICLE_CASES` в начале `make_figures.py`.
- Расчет **не импортирует** визуализацию и наоборот: `make_figures.py` тянет matplotlib и PIL,
  но обращается к `paraphin` только за данными и константами. Не переносите сюда логику,
  которая должна остаться в основном расчете.
