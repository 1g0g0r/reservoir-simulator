# Неструктурированные сетки (честный МКО) при сохранении регулярных: оценка

Разбор кода на 2026-10-07, без правок. Итог: задача посильная, если регулярную сетку оставить отдельной веткой (флаг
`grid_type` уровня модуля, как остальные флаги), а неструктурированную хранить как «сетку `Nx = N_ячеек, Ny = 1`»:
тогда поячеечные ядра не меняются вовсе, переписывается только то, что смотрит на соседей. Минимальная рабочая
версия - 2-3 недели, с быстрым решателем давления и сверкой с MRST - 5-8 недель. Главная цена не в коде, а в шаге
по времени: сгущение у скважин при явной схеме по насыщенности уменьшает шаг пропорционально квадрату размера
ячейки скважины (раздел 4).

## 1. Что в коде привязано к регулярной сетке

| Часть | Где | Привязка |
|---|---|---|
| Поячеечные ядра (~25 функций, ~400 обращений `[i, j]`) | `equations/*`, `solver.py` | только своя ячейка `(i, j)` - переносятся без правок при `Ny = 1` |
| Объем ячейки, шаги сетки | `volume`, `hx`, `hy` в ~10 файлах ядер (`Temperature`, `Saturation`, `Wp_balance`, `Deposition`, `Components`, `_calc_dt`, ...) | константы `constants.py` -> массив объемов ячеек |
| Перетоки через грани | `Flows_in_cells.py` | 4 грани, `DI/DJ/HIJ/AREA` (`FVM_utils.py`), фиктивная ячейка за границей по вылету индекса |
| Перенос компонентов | `Components.py` | потоки граней в `rows[i, ROW_FO]` длины 4 |
| Градиент давления | `Average_velocity.calc_Um_r2` | центральные разности по x, y |
| Матрица давления | `Pressure._fill_matrix_and_rhs` | пятиточечный шаблон, три диагонали |
| Решатель давления | `mg_solver.py`, `guess.py` | агрегация 2x2 по уровням с рамкой, красно-черный порядок по `(i + j) % 2`, шаблон в проекции |
| Граничные условия | `boundary_conditions.py` | 4 стороны прямоугольника (`Bound`), граница - по выходу индекса за сетку |
| Скважины | `utils/well.py` | ячейка `(i, j)`; Писман `r_e = 0.14*sqrt(hx^2 + hy^2)` (`constants._re`) |
| Выгрузка и графики | `save_data_fields.py`, `visualisation*.py`, `graphs.py`, dash | поля `(Nx, Ny)`, карты `Contour`/`Heatmap` на `x, y` |
| Опыты, статья, тесты | `experiments/`, `твт_статья_АСПО/`, `tests/` | регулярная сетка (керн `Nx = 1`) - остаются на регулярной ветке |

Соседей по пространству читают 6 модулей: `Flows_in_cells`, `Components`, `Average_velocity`, `Pressure`, `mg_solver`,
`guess`. Совпадения `i - 1`/`i + 1` в `Pore_bundle.py` и `Qp_m_k_fi.py` - соседи по радиусу пор, сетки не касаются.

## 2. Как добавить, не ломая регулярный интерфейс

1. **Сетка - объект с одинаковой структурой для обоих видов** (`paraphin/mesh.py`): центры и объемы ячеек; грани -
   пары ячеек, площадь, расстояния от центров до грани (для двухточечной аппроксимации, TPFA); граничные грани с
   метками; список граней ячейки в CSR (`cell_faces_ptr`, `cell_faces`). Регулярная сетка строится тем же
   генератором - на ней новую ветку сверяют со старой.
2. **Поля неструктурированной сетки - массивы `(N, 1)`** (`Nx = N`, `Ny = 1` в `constants.py`, читается из файла
   сетки при импорте). Все поячеечные ядра, `prange` по `i`, скретч `rows[i]`, выгрузка по формам работают как есть.
   Сброс кеша numba (`paraphin/__init__.py`) должен учитывать и хеш файла сетки.
3. **Флаг `grid_type = 'regular' | 'unstructured'`** - константа уровня модуля: numba сворачивает ветку, регулярный
   расчет остается побитово прежним (`test_regression_flags_off`), как требует правило «старые ядра не править».
   Сиблинги для неструктурированной ветки:
   - `flows_in_cells_u` - цикл по граням ячейки из CSR вместо `range(4)`; проводимость грани
     `T = A/(d1/k1 + d2/k2)`, вверх по потоку - как сейчас;
   - перенос компонентов: строка `ROW_FO` длины `NF_MAX` (наибольшее число граней ячейки);
   - градиент давления (`calc_Um_r2`): Грин-Гаусс по граням или МНК по соседям;
   - матрица давления в CSR, проекция начального приближения - через CSR-умножение;
   - ГУ: метки граничных граней; для прямоугольной области метки Left/Right/Top/Bottom те же, `add_bc` не меняется;
   - скважины: ячейка по координатам (`add_well(x=..., y=...)` рядом с `i, j`), `r_e` Писмана для многоугольной
     ячейки (Peaceman 1983: `r_e ~ 0.2*sqrt(A)` для изотропной).
4. **Объем ячейки** - массив вместо константы `volume`. Если для регулярной сетки подставлять массив из той же
   константы, значения побитово те же, но это правка сигнатур старых ядер; безопаснее держать массив только в
   неструктурированной ветке.
5. **Решатель давления.** Первый шаг - прямой SuperLU из `sparse_numba` (уже в окружении): работает сразу, но на
   10^4 ячеек ~в 10-30 раз медленнее нынешнего многосеточного (замеры прежних решателей - `docs/PERFORMANCE_FINDINGS.md`).
   Затем - PCG с алгебраической агрегацией (парное сопоставление по сильным связям, операторы Галеркина в CSR,
   Гаусс-Зейдель с раскраской или Чебышёв-Якоби, грубый уровень - Холецкий). Это самая трудоемкая часть.
6. **Выгрузка и графики.** В итоговый файл - геометрия (многоугольники ячеек). Карты: matplotlib `PolyCollection`/
   `tripcolor`; в dash - многоугольники или интерполяция на растр (`scipy.interpolate.griddata`) для `Heatmap`.

**«Честный МКО» и TPFA.** Двухточечная аппроксимация потока согласована только на K-ортогональных сетках: грань
перпендикулярна отрезку между центрами (PEBI/Вороной, прямоугольники). На произвольных треугольниках и скошенных
четырехугольниках нужна многоточечная (MPFA) - это еще 2-4 недели и несимметричная матрица давления. Поэтому
рекомендуется PEBI-сетка (Вороной): TPFA на ней честная, а сгущение к скважинам и разломам строится естественно.

## 3. Трудоемкость

| Этап | Оценка |
|---|---|
| `mesh.py`: генерация/чтение, геометрия, CSR, регулярная сетка тем же кодом, тесты геометрии | 3-5 дней |
| Поля `(N, 1)`, объемы ячеек, флаг `grid_type`, хеш сетки в сбросе кеша | 1-2 дня |
| Перетоки, перенос компонентов, градиент, ГУ, скважины (сиблинги) | 5-8 дней |
| Давление: сборка CSR + SuperLU (минимальная версия) | 1-2 дня |
| Выгрузка, графики, dash | 2-4 дня |
| Проверки: неструктурированная ветка на регулярной сетке против регулярной (до округления), балансы масс, MRST на PEBI | 4-6 дней |
| **Минимальная версия** | **2-3 недели** |
| Алгебраический многосеточный PCG + проекция в CSR до скорости нынешнего решателя | +1.5-3 недели |
| Борьба с мелким шагом у скважин (раздел 4) | +1-3 недели |
| MPFA для неортогональных сеток (если понадобится) | +2-4 недели |

Риски: ячейка с переменным числом граней сбивает векторизацию цикла по граням (сейчас он векторизуется, см.
`CLAUDE.md`) - на ячейку ждать в 1.5-2 раза дороже регулярной; ловушка типов индексов в `prange`
(`CLAUDE.md`, «Ловушка numba в parfor») при переборе соседей через CSR.

## 4. Шаг по времени при сгущении у скважин

Схема IMPES: насыщенность, температура и перенос явные, шаг выбирается по Куранту (`_equations_loop`, `_calc_dt`).
Для ячейки скважины

    dt <= CFL * m * V / (max|f_w'| * (Q_отток + |q_скв|)),

а дебит скважины `q` от размера ячейки почти не зависит (его задают забойное давление и пласт). Значит,
**dt ячейки скважины ~ V ~ h^2**. Для ячеек при сгущении `h ~ r` (геометрическая прогрессия от скважины) поток
через ячейку ~ `q*h/(2*pi*r)`, и предел `dt ~ h*r ~ h^2` - решает самая мелкая ячейка. Теплопроводность (тоже
явная, входит в тот же предел через `_cond`) дает `dt ~ psi*h^2/(4*lambda)`: при `psi ~ 2.5e6 Дж/(м^3 К)`,
`lambda ~ 2 Вт/(м К)` это ~1.2·10^4 с даже при h = 0.2 м - не ограничивает.

**Замер на нынешней сетке 75x75 (h = 2.67 м), постановка `start.py`.** Шаг уже сейчас задает ячейка
нагнетательной скважины:

| Время | Шаг | Предел по обычным ячейкам | Предел ячейки нагнетательной / добывающей |
|---|---:|---:|---:|
| 100 сут (5 280 шагов) | 1587 с | 3174 с | 1587 / 3430 с |
| 1000 сут (73 532 шага) | 868 с | 1737 с | 868 / 1877 с |

**Оценка при сгущении** (шаг делится на `(2.67/h_min)^2`):

| Ячейка у скважины h_min | Во сколько раз меньше шаг | Шаг на 1000 сут | Замечание |
|---:|---:|---:|---|
| 2.67 м (как сейчас) | 1 | 868 с | |
| 1.0 м | ~7 | ~120 с | граница применимости Писмана при rw = 0.1 м: `r_e = 0.2*h = 0.2 м = 2*rw` |
| 0.5 м | ~28 | ~30 с | `r_e ~ rw`, модель Писмана неприменима |
| 0.2 м | ~180 | ~5 с | ниже `dt_min = 4.3 с` (`constants.py`): шаг упрется в нижнюю границу, схема станет неустойчивой |

Расчет на 9 лет сейчас - сотни тысяч шагов; при h_min = 0.2 м шагов станет в ~180 раз больше, то есть часы-сутки
вместо минут. Кроме того, мельче ~1 м модель скважины Писмана не годится: скважину придется задавать внутренней
границей радиуса `rw` (грани ячеек вокруг ствола), это отдельная правка `well.py` и сборки давления.

**Что с этим делать** (по цене):

1. **Не сгущать, а оставить Писмана** - если цель - дебиты и фронт заводнения, сгущение не нужно: профиль давления
   у скважины Писман учитывает аналитически.
2. **Радиальная подмодель призабойной зоны** - одномерная радиальная сетка от `rw` до `r_e` внутри ячейки
   скважины со своими подшагами, связанная с крупной ячейкой через дебит. Ровно та зона, где идет кольматация (скин),
   и ровно та техника, что уже есть для одномерного керна (`experiments/core_runner.py`). Шаг крупной сетки не
   меняется. Оценка - 1-2 недели; не требует неструктурированных сеток вовсе.
3. **Локальный шаг (подшаги переноса в мелких ячейках)** - давление раз за глобальный шаг, насыщенность,
   температура и состав в зоне сгущения - подшагами со своим Курантом; консервативность на границе мелкой и крупной
   зон через накопленные потоки граней. Глобальный шаг вырастет даже по сравнению с нынешним (сейчас его держит
   ячейка скважины). Оценка - 1-2 недели поверх неструктурированной ветки; осторожно с ограничителями подводом
   в кинетике (они считаются от шага).
4. **Адаптивно-неявная схема (AIM)** - неявные насыщенность, температура и состав в ячейках у скважин (Ньютон на
   маленькой подсистеме). Самая устойчивая, но с кинетикой осаждения и детальным составом - самая дорогая: 3+ недели.

## 5. Чем строить неструктурированные сетки

| Инструмент | Что дает | В окружении | Оценка |
|---|---|---|---|
| `scipy.spatial.Voronoi` / `Delaunay` | PEBI-сетка по набору точек: фон (решетка или случайные точки) + кольца точек вокруг скважин с геометрическим шагом | есть | **рекомендуется для начала**: K-ортогональна, полный контроль сгущения, без новых зависимостей. Нужна обрезка ячеек по прямоугольнику (свой код ~50 строк или `shapely`) |
| MRST, модуль `upr` (`pebiGrid`, `compositePebiGrid`, `clippedPebi2D`) | PEBI со сгущением к скважинам и разломам, готовая геометрия (`computeGeometry`), решатели `incompTPFA` | Octave + MRST уже используются в `tests/mrst_tests` | **для эталонов**: та же сетка и в MRST, и в paraphin (экспорт `G.cells`, `G.faces` в JSON) - сверка на одной сетке |
| `gmsh` (Python API) + `meshio` | треугольники/четырехугольники с полями размера (Distance/Threshold у скважин), сложные границы, разломы | нет (`pip install gmsh meshio`) | для сложной геометрии; для TPFA брать двойственную сетку Вороного треугольников или следить за остроугольностью |
| `triangle` (Shewchuk) | Делоне с ограничениями качества, диаграмма Вороного (`-v`) | нет | компактная альтернатива gmsh для 2D |
| `shapely` | обрезка ячеек Вороного областью, полигоны для графиков | нет | вспомогательная |
| `matplotlib` (`PolyCollection`, `tripcolor`) | карты на многоугольниках | есть | для `graphs.py`/статьи; в dash - многоугольники plotly или растр |

## 6. Рекомендация

1. Сначала решить, зачем сгущение. Если ради призабойной кольматации - радиальная подмодель (п. 4.2) дешевле и
   точнее, чем неструктурированная сетка с мелким шагом.
2. Если нужна геометрия (неправильная форма залежи, разломы, кусты скважин) - PEBI на `scipy.spatial.Voronoi`,
   ветка `grid_type`, поля `(N, 1)`, SuperLU для давления; MRST `upr` для эталона на той же сетке.
3. Многосеточный решатель на CSR и локальный шаг - когда минимальная версия покажет, что решатель или шаг
   действительно упираются.
